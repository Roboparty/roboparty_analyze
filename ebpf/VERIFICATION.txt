USB giveback tracer: board verification, 2026-10-21

Run on board:
  bash /root/ebpf/run-usb-giveback.sh 120 5000
Arguments: duration in seconds, slow threshold in microseconds.
The wrapper requires exactly one USB 1209:2323 device and detects its current
bus/device numbers. Logs go into /root/ebpf/results (override with OUTPUT_DIR).
Exit codes: 0 = completed with paired samples; 2 = no paired samples;
other nonzero codes indicate a setup, tracing, or logging error.

Scope:
  These are control-endpoint tests of the tracer, not bulk CAN load tests.
  can0..can3 remained DOWN. No motor commands or CAN frames were generated.
  This does not reproduce or rule out the earlier 906 ms stall.
  T1 is usb_hcd_giveback_urb entry, before actual list insertion.
  T2 is __usb_hcd_giveback_urb entry, before usbmon C and driver callback.
  T2-T1 includes locking, queueing, earlier callbacks and dispatch delays;
  it is not pure scheduler latency or USB wire transfer time.
  The script uses bpftrace's default nsecs clock; do not subtract wall-clock
  usbmon timestamps directly. Tracing overhead was not benchmarked.
  Unmatched T1 entries at shutdown can include ordinary in-flight requests.
  No data was collected from bulk endpoints 0x81/0x02 during these tests.
